# Knightfall

Chess trainer: rated puzzles, daily, rush, live 1v1 battle, custom puzzles, and a Stockfish game review.
`README.md` describes every mode and the deploy setup. This file covers what the README does not: how to
work in the code without breaking it.

## Commands

Run from the repo root (npm workspaces).

| Command | What it does |
| --- | --- |
| `npm run dev` | Web on :5173 and the battle/API server on :8787 |
| `npm run typecheck` | `tsc` in every workspace |
| `npm test` | All unit tests (vitest, about 450 tests, about 6 s) |
| `npm run build` | Production build of web and server |

A change is done when `npm run typecheck`, `npm test` and `npm run build` all pass. CI runs the same three
on Node 22. For anything visible, also check it in the browser with `npm run dev`.

## Layout

- `packages/core`: pure TypeScript with no DOM or Node APIs, shared by web and server. Puzzle types, move
  judging, Glicko-2, seeded sequences, the battle wire protocol, and all game-analysis math
  (`src/analysis/`).
- `apps/web`: Vite + React 19 + Tailwind 4. `src/features/<mode>/` holds one folder per mode,
  `src/shared/` holds what several modes use (Board, PuzzlePlayer, engine pool, db, importers).
- `apps/server`: Node `http` + `ws`. Battle matchmaking and rooms, plus the chess.com game lookup.
- `scripts/`: one-off data builders. `data/` is gitignored and holds large downloads.

## Conventions

- **Logic lives outside components.** Each feature keeps its rules in a plain `.ts` file (`rushLogic.ts`,
  `dailyLogic.ts`, `reviewLogic.ts`) with a `.test.ts` beside it. Components and hooks call into it. New
  behavior goes in the logic file with a test first, then gets wired into the UI.
- **Imports use the `.ts` suffix** (`from './types.ts'`), and type-only imports use `import type`.
  `verbatimModuleSyntax` makes the second one a compile error if you forget.
- **`@knightfall/core` is consumed as source.** There is no build step for it, so a change there is
  picked up by web and server immediately. The server uses it too, so keep it free of browser APIs.
- **`noUnusedLocals` and `noUnusedParameters` are on.** Delete what you stop using.
- **Commit messages** are a plain sentence led by the area, for example
  `Game Review: build reports in a Web Worker (...)`. No `feat:`/`fix:` prefixes.

## Things that break silently

- **IndexedDB schema (`apps/web/src/shared/db.ts`).** All user progress lives in the browser and there are
  no accounts, so there is no way to repair a user's data after a bad release. Never edit an existing
  `db.version(n).stores(...)` block. To change the schema, add `db.version(n + 1)` with an upgrade
  function, and make new fields optional so old rows still load.
- **Battle protocol (`packages/core/src/protocol.ts`).** Web and server deploy separately (Vercel and
  Render), so for a while after any deploy an old client talks to a new server or the reverse. Message
  changes must be backward compatible.
- **Engine files (`apps/web/public/engine/**`).** Stockfish is GPL and is shipped unmodified. These files
  must stay byte-identical to upstream (`.gitattributes` turns off line-ending conversion for them).
  Never edit, reformat or regenerate them by hand; `npm run engine` fetches them.
- **Puzzle and opening data (`apps/web/public/puzzles/`, `openings.json`).** Generated by `scripts/`.
  Change the script and rerun it; do not hand-edit the JSON.
- **The daily puzzle is the same for everyone.** It comes from a seeded picker in `packages/core`.
  Changing the picker, the seed or the order of `daily-pool.json` changes history for every player.
- **Game Review numbers are calibrated.** Move classification and accuracy in
  `packages/core/src/analysis/` are tuned to match a reference site, and the accuracy-by-rating curve is
  fitted by `scripts/fit-rating.mjs`. Thresholds there are not arbitrary. A change to one needs a test
  that shows the intended before and after, and the existing classify/report tests must still pass
  unchanged unless the user asked for the behavior change.
- **Heavy work stays off the main thread.** Engine analysis runs in a worker pool and report building
  runs in a Web Worker. Do not move either back onto the page.

## Rules for network and deploys

- The app only talks to the endpoints listed under "Network use" in the README and never sends
  credentials. Adding any new network call means updating that section too.
- Pushing to `main` deploys: Vercel rebuilds the site and Render redeploys the battle server. Do not push
  or commit unless asked.
- New third-party code or assets need an entry in `THIRD_PARTY_NOTICES.md` and a compatible license.
